**Implements:** follow-up to `07. Discovery, Pairing & Config Sync.spec.md`
— desktop-side debug affordance, no protocol change.
**TL;DR:** let the desktop show whether a device is connected right now and
force-close that connection on demand, gated behind a persisted "debug
tools" toggle available to end users, not just dev builds.

## Scope

**In:**
1. **Persisted "debug tools" toggle** — a boolean preference (`buttons.json`
   or a sibling prefs file; exact home is implementer's call), default
   off. Available to any end user, not compiled out of release builds —
   decided 2026-09-13: gate at runtime, not `cfg!(debug_assertions)`. How
   the toggle itself is revealed (a visible Settings switch vs. a hidden
   gesture, à la mobile-OS developer options) is an open implementation
   decision.
2. **Connection status** — a Tauri command exposing whatever `ConnSlot`
   currently holds: connected-or-not, peer address, connected-since.
   Needs `ConnectionHandle` (`server.rs`) to actually carry `addr` and a
   timestamp — it doesn't today.
3. **Force-disconnect** — a Tauri command that closes the current
   connection and *clears* the slot to `None`. Distinct from the existing
   eviction path (`server.rs`), which only ever replaces the slot as a
   side effect of a new authenticated connection — nothing today empties
   it without a replacement.
4. A small debug view in the desktop UI (behind the toggle) surfacing 2-3
   above.

**If this view ever lists live Bonjour advertisements (not just the
current connection)**: display the instance name each browse result
actually reports, never the locally configured preference. mDNS silently
renames a colliding instance ("Buttons Desktop (2)", RFC 6762 §9) — two
machines sharing a configured name can end up advertising different
strings, and showing the configured one would lie about what's actually on
the wire. Verify before relying on this: run two desktop instances with
the same configured name and check what `NWBrowser` reports for each.

**Out:**
1. Any connection *history* or log viewer — that's the "Observability
   beyond local logging" EDD §7 already named and deferred; this stays
   scoped to *current* state only.
2. Any change to the eviction/reconnect logic itself (Implementation
   Notes #9 of slice 07) — this only adds a manual, deliberate way to
   trigger the same close path a real eviction already uses.

> **Rule for agent:** stay inside this scope. If something out of scope
> blocks you, stop and flag it — don't silently expand scope to route
> around it.

## Files to Touch

1. `desktop/src-tauri/src/server.rs` — modify — `ConnectionHandle` gains
   `addr`/`connected_at`; a way to read slot state and to clear it
   (not just replace it).
2. `desktop/src-tauri/src/lib.rs` — modify — new Tauri commands for status
   and force-disconnect. Illustrative, not final — names/shapes are open
   to change during implementation:

   ```rust
   #[derive(Serialize, Clone)]
   struct ConnectionStatus {
       connected: bool,
       peer_addr: Option<String>,       // "192.168.1.42:54211"
       connected_since: Option<String>, // epoch seconds, matches
                                         // pairing.rs's `paired_at` convention
   }

   #[tauri::command]
   async fn get_connection_status(
       slot: tauri::State<'_, ConnSlot>,
   ) -> Result<ConnectionStatus, String> { /* ... */ }

   #[tauri::command]
   async fn force_disconnect(
       slot: tauri::State<'_, ConnSlot>,
   ) -> Result<bool, String> { /* true = something was connected and is now closed */ }
   ```

   Sample calls — both take no arguments; a markdown table cell can't hold
   a fenced code block (GFM table cells are inline-only), so input/output
   are stacked rather than side by side:

   `get_connection_status()` — input: *(none)*

   ```json
   {
     "connected": true,
     "peerAddr": "192.168.1.42:54211",
     "connectedSince": "1757774531"
   }
   ```

   — or, nothing connected:

   ```json
   {
     "connected": false,
     "peerAddr": null,
     "connectedSince": null
   }
   ```

   `force_disconnect()` — input: *(none)*

   ```json
   true
   ```

   — or, nothing to disconnect:

   ```json
   false
   ```
3. Desktop settings UI — modify/create — the debug-tools toggle and, when
   on, the status/disconnect view.

## Definition of Done

1. [ ] With the debug toggle off (default), no debug UI is reachable.
2. [ ] With it on, the desktop shows whether a phone is currently
       connected, its address, and how long it's been connected.
3. [ ] A "Disconnect" action closes that connection and the phone falls
       back to `PairingView` (per the drop-detection fix already shipped
       in slice 07) — without restarting either app.
4. [ ] The slot is actually empty after a manual disconnect — a
       subsequent status check shows nothing connected, not a stale
       entry.

**Verification:**
```
cd desktop/src-tauri && cargo build
cd desktop && npm run check
# manual: pair a real device, enable debug tools, disconnect it from the
# desktop UI, confirm the phone drops to PairingView and auto-reconnects
# (per slice 07's drop-reconnect fix) without either app restarting.
```
