**Implements:** `01. Architecture Overview.edd.md`, Testing & Rollout Plan step 2.
**TL;DR:** Render a hardcoded grid of buttons (icon + label) in the desktop app
against dummy data — no backend, no persistence, no networking, no protobuf — to
validate the visual/data shape before any schema work (EDD §5.2 sequencing).

---

## Scope

**In:**
- A Svelte component rendering a CSS Grid of buttons from a hardcoded mock array.
- Each button shows an icon and a text label.
- Basic single-style visual treatment (not full theming).

**Out:**
- Editing (add/remove/reorder) — roadmap step 3.
- Folders, pages, Profiles — roadmap step 4.
- Persistence of any kind — roadmap step 3.
- Light/dark theme switching — later polish, not this slice.
- Any Tauri IPC/backend call — pure frontend, mock data only.
- Click/press behavior beyond a CSS hover/active affordance — buttons are
  visually static, per the slice name.

> **Rule for agent:** stay inside this scope. If something out of scope blocks
> you, stop and flag it — don't silently expand scope to route around it.

## Files to Touch

- `/desktop/src/lib/components/ButtonGrid.svelte` — create — the grid component.
- `/desktop/src/lib/data/mockButtons.ts` — create — hardcoded mock button array.
- Desktop app's root route/page (exact path depends on the Tauri+Svelte template
  generated in slice 1 — confirm before editing) — modify — render `ButtonGrid`.

> **Rule for agent:** don't touch files outside this list without flagging it
> first. If the slice-1 scaffold's file layout doesn't match these paths,
> correct this list to match reality rather than guessing.

## Interface / Data Contract

Provisional, frontend-only shape — intentionally informs but does not commit the
future `.proto` schema (EDD §5.2):

```ts
interface MockButton {
  id: string;
  label?: string;
  icon?: string; // path or data URI
}
```

## Implementation Notes

- CSS Grid for layout (EDD §5.5) — confirm it wraps sensibly at a few different
  window sizes.
- Mock dataset: 6-8 buttons is enough to see wrapping behavior; no need for more.
- No Rust/Tauri command calls in this slice — everything lives in the frontend.

## Definition of Done

- [ ] Desktop app launches and displays a grid of mock buttons with icon + label.
- [ ] Grid uses CSS Grid and wraps sensibly when the window is resized.

**Verification:**
```
cd desktop && npm run tauri dev
```
Visually confirm the grid renders correctly; no automated test for pure layout
at this stage.

> **Rule for agent:** run the verification command above and visually confirm
> the result before declaring this slice done — don't assume it passed.

## Rollback

Low risk — pure frontend, no persisted state, no backend touched. If something's
wrong, fix forward rather than reverting.
